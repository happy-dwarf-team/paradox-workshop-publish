# steamcmd login in CI: Steam Guard, session lifetime, game ownership and runners

Research for [#3](https://github.com/happy-dwarf-team/paradox-workshop-publish/issues/3). Checked on 2026-10-20. Nothing was run against Steam and no account was used. Each claim carries one of three labels:

- **[doc]**: stated in Valve's, Steam Support's or GitHub's own documentation.
- **[code]**: read in the source code of a tool, pinned to a commit or tag.
- **[community]**: reported in an issue, forum post or third-party write-up and not reproduced by us.

Tools that are already compared in [prior-art.md](https://github.com/happy-dwarf-team/paradox-workshop-publish/blob/research/prior-art/docs/research/prior-art.md) are cited here only for login behaviour.

## Short answer

- A GitHub-hosted runner is a new, unrecognized device on every run, so Steam Guard asks for a code each time unless the run brings a session with it.
- Of the three ways to answer Steam Guard, only two work without a person: a **cached session** (`config/config.vdf` from an earlier interactive steamcmd login, then `+login <user>` with no password) and **TOTP** codes computed from the mobile authenticator's `shared_secret`, sent together with the password. Email codes need a person on every run.
- The account must hold a non-temporary licence for the game. Family Sharing and free weekends are not enough, and limited accounts (under 5 USD spent) cannot submit Workshop content.
- Only the item's owner can update its files. Contributors cannot.
- steamcmd runs natively on `ubuntu-latest`, `windows-latest` and `macos-latest`, so a Docker image is not needed. Valve does not document its exit codes or its success output.
- Recommendation: use the cached session for E4 and as the modders' default. Offer TOTP only as an opt-in for accounts that already keep their `shared_secret` outside the official app. See [Recommendation](#recommendation).

## Steam Guard options

### Background: what Steam asks for

- With Steam Guard on, "you'll need to provide a special code to login from an unrecognized device", either by email or from the Steam Mobile app **[doc]** ([Steam Guard FAQ](https://help.steampowered.com/en/faqs/view/06B0-26E6-2CF8-254C)).
- Valve's CI recipe for steamcmd: log in once with password and Steam Guard code on the build machine. On later runs, pass only the user name (`+login <username>`) and keep `<Steam>\config\config.vdf` "saved and preserved between runs, as this file may be updated after a successful login". Logging in again with the password issues a new Steam Guard token that is then required **[doc]** ([Uploading to Steam](https://partner.steamgames.com/doc/sdk/uploading)).
- A denied login (`Account Logon Denied`) is resolved with `set_steam_guard_code <code>` and a fresh login **[doc]** (same page).

### 1. Cached session (`config.vdf`)

- **Obtaining it.** Run `steamcmd +login <user>` once by hand, enter the password and the email or mobile code, and confirm that `+login <user> +quit` no longer prompts. Then base64-encode `config/config.vdf` and store it as a secret **[code]** ([steam-deploy README @ c9e2aef](https://github.com/game-ci/steam-deploy/blob/c9e2aef08b9a3509645a42c24940ccff05588ebe/README.md#configvdf)). This works with both email and mobile Steam Guard, because the person answers the prompt once.
- **Using it.** game-ci/steam-deploy v3.2.1 decodes the secret into `$HOME/Steam/config/config.vdf` and uploads with `+login "$steam_username"` without a password **[code]** ([steam_deploy.sh @ v3.2.1, L136 and L175](https://github.com/game-ci/steam-deploy/blob/v3.2.1/steam_deploy.sh#L136)). game-ci/cli omits the password when it is unset, "not passed as \"\"" **[code]** ([steamcmd-runner.ts @ 7da0cea, L88-L99](https://github.com/game-ci/cli/blob/7da0cea2f31799a4cbd79c1d452c254023f4f678/plugins/steam-deploy/src/steamcmd-runner.ts#L88-L99)).
- **What it holds.** The file holds the login token. A trial on Windows found that steamcmd accepts the whole file, or the file without its `CMWebSocket` server list, but not `ConnectCache` alone **[community]** ([Aureliolo/steamship #54](https://github.com/Aureliolo/steamship/pull/54), 2026-09). Since 2022 the Steam client logs in with refresh tokens, which are JWTs "valid for ~200 days" according to the node-steam-user maintainer **[community]** ([node-steam-user README @ 02818bd, L622-L624](https://github.com/DoctorMcKay/node-steam-user/blob/02818bd08090b58ff54f1d9ce0073319b8e1eef7/README.md?plain=1#L622-L624)). Valve does not say that steamcmd stores exactly this token, or for how long it stays valid.
- **Renewal.** Steam can issue a new refresh token when an access token is generated, and SteamKit2 notes the new token "may be an empty string" **[code]** ([AccessTokenGenerateResult.cs @ 49387ae](https://github.com/SteamRE/SteamKit/blob/49387aec55c24104946af7a7b160148358e538b4/SteamKit2/SteamKit2/Steam/Authentication/AccessTokenGenerateResult.cs)). node-steam-session documents that once a token is renewed, "the old refresh token will become invalid, even if it is not yet expired" **[code]** ([README @ 3ac0f34, L472-L482](https://github.com/DoctorMcKay/node-steam-session/blob/3ac0f34fd964b3f886ba18ef4824ac43c942e030/README.md?plain=1#L472-L482)). Together with Valve's "may be updated" note, this means a runner that throws away an updated `config.vdf` could be left holding a dead secret. Whether steamcmd actually rotates the token is not documented. One project writes the file back into an organisation secret after each run, using a PAT **[community]** ([steam-deploy #77](https://github.com/game-ci/steam-deploy/issues/77)).
- **How long it lasts, and what ends it.**
  - When the session expires, steamcmd fails with `Logging in user ... to Steam Public...FAILED (License expired)`, and the fix is a new local login and a new secret **[code]** ([steam-deploy README](https://github.com/game-ci/steam-deploy/blob/c9e2aef08b9a3509645a42c24940ccff05588ebe/README.md#configvdf)).
  - "Deauthorize all devices" in Manage Steam Guard makes every device look new again **[doc]** ([Steam Guard FAQ, #deauthorize](https://help.steampowered.com/en/faqs/view/06B0-26E6-2CF8-254C)).
  - A password login on the same machine issues a new token **[doc]** ([Uploading to Steam](https://partner.steamgames.com/doc/sdk/uploading)).
  - In 2023, passing the password in CI let a `config.vdf` work for one run only. The fix was to drop the password **[community]** ([steam-deploy #56](https://github.com/game-ci/steam-deploy/issues/56), [PR #57](https://github.com/game-ci/steam-deploy/pull/57)).
  - The newest unreleased steam-deploy wrapper makes `password` required again **[code]** ([README @ c9e2aef, L11-L14](https://github.com/game-ci/steam-deploy/blob/c9e2aef08b9a3509645a42c24940ccff05588ebe/README.md?plain=1#L11-L14)). We should not copy that.
- **Size.** GitHub secrets are capped at 48 KB **[doc]** ([GitHub secrets](https://docs.github.com/en/actions/reference/security/secrets)). A base64 `config.vdf` has gone over that cap, and gzip before base64 solved it **[community]** ([steam-deploy #77](https://github.com/game-ci/steam-deploy/issues/77)). Dropping the server list brought one file from 14.6 KB down to 1.6 KB **[community]** ([steamship #54](https://github.com/Aureliolo/steamship/pull/54)).
- **Exposure if it leaks.** A leak gives away a session, not the password or the 2FA secret. The owner can revoke it by deauthorizing devices **[doc]** ([Steam Guard FAQ](https://help.steampowered.com/en/faqs/view/06B0-26E6-2CF8-254C)). The Actions cache must not hold it (see prior-art: [buildalon note](https://github.com/happy-dwarf-team/paradox-workshop-publish/blob/research/prior-art/docs/research/prior-art.md#github-actions-and-clis-that-use-steamcmd)).

### 2. TOTP from `shared_secret`

- **Algorithm.** HMAC-SHA1 over `floor(unix_time / 30)`, with the result mapped to five characters from `23456789BCDFGHJKMNPQRTVWXY` **[code]** ([node-steam-totp index.js @ 359c2d5](https://github.com/DoctorMcKay/node-steam-totp/blob/359c2d57b480c0808474416367530797e64ef773/index.js)). The mobile authenticator "will automatically generate a new code every 30 seconds" **[doc]** ([Steam Guard FAQ, #code](https://help.steampowered.com/en/faqs/view/06B0-26E6-2CF8-254C)). In CI the code is generated in a step, for example with [CyberAndrii/steam-totp](https://github.com/CyberAndrii/steam-totp/blob/1661caebf0a84a79be0166020f81837039137101/action.yml), and passed as `+login <user> <password> <code>` or through `+set_steam_guard_code` **[code]** ([setup-steamcmd integration.yml @ afc45f1, L82](https://github.com/CyberAndrii/setup-steamcmd/blob/afc45f145b95c175c3a3862d3ca84756537d48e8/.github/workflows/integration.yml#L82)).
- **Obtaining `shared_secret`.** The secret belongs to the authenticator that was registered on the account. A tool such as steamguard-cli gets it by becoming that authenticator, either through a fresh `setup` or by replacing an existing one. Replacing has two paths, and both lock trading:
  - "transfer" through SMS, with a 2-day trade ban;
  - revocation with the `R#####` code, with a 15-day trade ban **[code]** ([steamguard-cli setup.rs @ b6c439c, L60-L68](https://github.com/dyc3/steamguard-cli/blob/b6c439c9c1768370b50b3365102fca384b225e9a/src/commands/setup.rs#L60-L68)).

  For a modder who already uses the Steam Mobile app, this means moving 2FA off the phone app.
- **How long it lasts, and what ends it.** The secret stays valid until that authenticator is removed or moved, since that is the only path in the source that replaces it **[code]** (same file). Each code is valid only for its 30-second window. One CI author waits 30 s between two logins because "the same code can't be used more than once" **[community]** ([integration.yml, L86](https://github.com/CyberAndrii/setup-steamcmd/blob/afc45f145b95c175c3a3862d3ca84756537d48e8/.github/workflows/integration.yml#L86)). The stored password stops working when it is changed.
- **Evidence it works on hosted runners.** setup-steamcmd's own CI publishes a real Workshop item (app 304930) on `ubuntu-latest` with password and TOTP, then downloads it and compares the bytes **[code]** ([integration.yml](https://github.com/CyberAndrii/setup-steamcmd/blob/afc45f145b95c175c3a3862d3ca84756537d48e8/.github/workflows/integration.yml)). The most recent push run passed on 2026-03-22 **[community]**: we read the run list, but its logs have expired.
- **Exposure if it leaks.** The secret store holds the password and the second factor, which is everything needed to log in from anywhere. This is the full account, not a session.

### 3. Email codes

- An email code is issued per login from an unrecognized device and replaced by the next one: "older codes will not work!" **[doc]** ([Steam Guard FAQ, #code](https://help.steampowered.com/en/faqs/view/06B0-26E6-2CF8-254C)). On a fresh runner, steamcmd stops at `Steam Guard code:` and fails with `Account Logon Denied` when no code is entered **[community]** ([steam-deploy #56](https://github.com/game-ci/steam-deploy/issues/56)). Email is therefore usable only to create the cached session (option 1). One archived HOI4 action read the codes over POP3, which is fragile and needs the mailbox password **[code]** (see prior-art: [Yard1](https://github.com/happy-dwarf-team/paradox-workshop-publish/blob/research/prior-art/docs/research/prior-art.md#github-actions-and-clis-that-use-steamcmd)).
- An approval in the Steam Mobile app (buildalon) needs a person on the first run and "from time to time" after that **[code]** ([buildalon/upload-steam README @ d8cbca4](https://github.com/buildalon/upload-steam/blob/d8cbca4f42fb606f93cf2185d5580f8e740e57f9/README.md)).

## New machine or IP: extra checks and locks

- **[doc]** Steam Guard keys on the *device*: an unrecognized device needs a code, and there is no limit on authorized devices ([Steam Guard FAQ, #limit](https://help.steampowered.com/en/faqs/view/06B0-26E6-2CF8-254C)). Valve documents no IP rule. The login result codes include `RateLimitExceeded` (84, temporary), `AccountLoginDeniedThrottle` (87, "possible attacker"), `TwoFactorCodeMismatch` (88), `InvalidLoginAuthCode` (65) and `AccountLogonDenied` (63) ([EResult](https://partner.steamgames.com/doc/api/steam_api#EResult)). We found no Valve page that describes locking an account for logging in from new IPs.
- **[community]** In 2023 `config.vdf` failed on the next run from a different machine or IP. After contact with Steam Support, a backend regression was reported fixed and username-only logins kept working across about a dozen runs ([steam-deploy #56](https://github.com/game-ci/steam-deploy/issues/56)). In 2026, `config.vdf` worked from France on hosted runners ([#90](https://github.com/game-ci/steam-deploy/issues/90)), and steamship ships the same pattern for Linux, Windows and macOS runners ([docs/ci.md @ fe88bf3](https://github.com/Aureliolo/steamship/blob/fe88bf33ad34153d427bd5c103049372a09ea39a/docs/ci.md)). One 2017 list of steamcmd failures includes `Login Failure: Rate Limit Exceeded (84)` with exit code 5 ([steam-for-linux #4341](https://github.com/ValveSoftware/steam-for-linux/issues/4341)). We found no report of an account lock caused by CI logins.
- **[doc]** These Steam-side holds can block publishing regardless of login method:
  - after "a recent password or email change, the user is not allowed to upload new content" (`k_EResultServiceReadOnly`);
  - hub bans, account locks and community bans give `InsufficientPrivilege`;
  - an active VAC or game ban gives `Banned` ([ISteamUGC CreateItemResult_t](https://partner.steamgames.com/doc/api/ISteamUGC#CreateItemResult_t)).

  Valve's SteamPipe build accounts must wait 3 days after security changes ([Uploading to Steam, Build Account](https://partner.steamgames.com/doc/sdk/uploading#Build_Account)). That page covers app builds, and the Workshop page gives no duration.

## Game ownership

- **[doc]** "Uploading to the Steam Workshop cannot be done by a user that has a temporary license for the game or tool that does the uploading", which rules out Family Sharing and free weekends ([Steam Workshop FAQ](https://partner.steamgames.com/doc/features/workshop)). `SubmitItemUpdate` returns `k_EResultAccessDenied` when "the user doesn't own a license for the provided app ID" ([SubmitItemUpdateResult_t](https://partner.steamgames.com/doc/api/ISteamUGC#SubmitItemUpdateResult_t)). steamcmd reports "Failed to get application info … (check login and subscription)" when the user lacks access to an app ([Uploading to Steam, errors](https://partner.steamgames.com/doc/sdk/uploading)).
- **[doc]** Limited accounts (under 5 USD spent) cannot submit Workshop content ([Limited User Accounts](https://help.steampowered.com/en/faqs/view/71D3-35C2-AD96-AA3A)). Items stay hidden until the author accepts the Workshop legal agreement ([Workshop implementation](https://partner.steamgames.com/doc/features/workshop/implementation)).
- **Inference.** The publishing account must own each target app outright: EU4 [236850](https://store.steampowered.com/app/236850), HOI4 [394360](https://store.steampowered.com/app/394360), Stellaris [281990](https://store.steampowered.com/app/281990), CK3 [1158310](https://store.steampowered.com/app/1158310), Victoria 3 [529340](https://store.steampowered.com/app/529340) and EU5 [3450310](https://store.steampowered.com/app/3450310) (IDs checked through the store `appdetails` API). This rules out a cheap dedicated publishing account: it would have to buy the game, and it would not own the modder's existing items.

## Contributors and items owned by another account

- **[doc]** Valve says "Authors of these items will be able to update their content any time" ([Steam Workshop](https://partner.steamgames.com/doc/features/workshop)). Neither `workshop_build_item` nor ISteamUGC has a call to add a contributor or transfer an item ([Workshop implementation](https://partner.steamgames.com/doc/features/workshop/implementation), [ISteamUGC](https://partner.steamgames.com/doc/api/ISteamUGC)).
- **[community]** Only the owner can edit the title and description, change visibility, update the item or delete it. Contributors can edit links, required DLC and items, and moderate comments ([Steam Discussions, 2020](https://steamcommunity.com/discussions/forum/0/2149847423930469260/)). Tabletop Simulator's knowledge base says "contributors cannot update your mod for you" ([TTS KB](https://kb.tabletopsimulator.com/custom-content/steam-workshop/)).
- **Consequence.** The secret must belong to the item's owner. A team mod can be published only from the owner's account, which matches the map's rule that every modder uses their own.

## Linux and Windows runners, and Docker

- **[doc]** Valve ships steamcmd for Windows (`builder`), Linux (`builder_linux`) and macOS (`builder_osx`) ([Uploading to Steam](https://partner.steamgames.com/doc/sdk/uploading)). Docker container actions run only on Linux runners ([GitHub: about custom actions](https://docs.github.com/en/actions/sharing-automations/creating-actions/about-custom-actions)). Docker-based Workshop actions therefore fail on Windows with `Container action is only supported on Linux` **[community]** ([steam-deploy #53](https://github.com/game-ci/steam-deploy/issues/53)).
- **[code]** setup-steamcmd downloads Valve's archive on all three OSes. On Linux it installs `lib32gcc-s1`, and on Windows it ignores exit code 7 on the first, self-updating run ([index.js @ afc45f1, L72 and L161](https://github.com/CyberAndrii/setup-steamcmd/blob/afc45f145b95c175c3a3862d3ca84756537d48e8/src/index.js#L161)). Its CI logs in on `ubuntu-latest`, `windows-latest` and `macOS-latest` ([integration.yml, L17-L18](https://github.com/CyberAndrii/setup-steamcmd/blob/afc45f145b95c175c3a3862d3ca84756537d48e8/.github/workflows/integration.yml#L17-L18)). Another Workshop action also treats exit code 7 as a quirk ([gruppe-adler steamcmd.ts @ 77e0138](https://github.com/gruppe-adler/action-release-to-steam-ws/blob/77e013810a69d28a27f08bfdb9ce50246bb46b13/src/steamcmd.ts)).
- **[community]** Arma mods are published with native steamcmd on `windows-latest` ([7Cav publish.yml](https://github.com/7Cav/7CavAddon/blob/18bc95ea274a432611a50e479dbeb6e2cf295019/.github/workflows/publish.yml)). Inside Docker, the default seccomp profile blocks a socket call that 32-bit steamcmd makes ([steamship docs/ci.md, L91-L94](https://github.com/Aureliolo/steamship/blob/fe88bf33ad34153d427bd5c103049372a09ea39a/docs/ci.md?plain=1#L91-L94)). One 2015 Linux report says only the directory tree was uploaded, not the files ([steam-for-linux #3997](https://github.com/ValveSoftware/steam-for-linux/issues/3997)).
- **Session location differs by install** **[code]**: `$HOME/Steam/config/config.vdf` in steam-deploy, `config/config.vdf` next to `steamcmd.exe` on Windows ([steam-deploy README](https://github.com/game-ci/steam-deploy/blob/c9e2aef08b9a3509645a42c24940ccff05588ebe/README.md#configvdf)).
- **Conclusion.** A Docker image is not needed. Native steamcmd on `ubuntu-latest` is the simplest path, and a Windows runner is a fallback. Whether a `config.vdf` made on Windows works on Linux is not documented (see the E4 risks).

## Rate limits, output and exit codes

- **Rate limits.** Valve documents no Workshop upload rate limit. Login has the temporary `RateLimitExceeded` (84) and `AccountLoginDeniedThrottle` (87) results **[doc]** ([EResult](https://partner.steamgames.com/doc/api/steam_api#EResult)). One Workshop error, a banned screenshot, imposed "a 1 day lockout of adding user content" **[community]** ([Unreal forums, 2016](https://forums.unrealengine.com/t/help-committing-update-error-failed-to-update-workshop-item-access-denied/68126)).
- **Exit codes.** Valve does not document them, and a 2016 request for documentation was closed without an answer from Valve ([steam-for-linux #4341](https://github.com/ValveSoftware/steam-for-linux/issues/4341)). Community values: 0 for success, 5 for login failures (84 and 88), 8 for install failures **[community]** (same issue). Tools do not trust exit codes:
  - game-ci/cli says steamcmd "can exit 0 without actually uploading anything" and requires a `PublishedFileId` line in the output **[code]** ([parse-workshop-output.ts @ 7da0cea](https://github.com/game-ci/cli/blob/7da0cea2f31799a4cbd79c1d452c254023f4f678/plugins/steam-workshop/src/parse-workshop-output.ts)). The plugin is experimental, and we did not see that line in a real log.
  - buildalon also accepts exit code 42 and fails on `Cached credentials not found.` **[code]** ([steamcmd.ts @ d8cbca4, L58 and L101](https://github.com/buildalon/upload-steam/blob/d8cbca4f42fb606f93cf2185d5580f8e740e57f9/src/steamcmd.ts#L101)).
- **Output.**
  - Login lines look like `Logging in user '***' to Steam Public...FAILED (Invalid Login Auth Code)` **[community]** ([steam-deploy #56](https://github.com/game-ci/steam-deploy/issues/56)).
  - Workshop steps print `Preparing update...`, `Uploading content...` and `Committing update...`, then `ERROR! Failed to update workshop item (<EResult>)` on failure. Seen examples are `(Invalid Parameter)` ([Weilbyte #5](https://github.com/Weilbyte/steam-workshop-upload/issues/5)) and `(Access Denied)` from ARK's uploader ([Unreal forums](https://forums.unrealengine.com/t/help-committing-update-error-failed-to-update-workshop-item-access-denied/68126)) **[community]**.
  - Valve documents only that on success the VDF's `publishedfileid` is rewritten with the item ID **[doc]** ([Workshop implementation](https://partner.steamgames.com/doc/features/workshop/implementation)).
- **Logs.** On failure, arma-actions prints `Steam/logs/stderr.txt`, `Steam/logs/workshop_log.txt` and `Steam/workshopbuilds/depot_build_<appid>.log` **[code]** ([entrypoint.sh @ e80cfb7, L31-L38](https://github.com/arma-actions/workshop-upload/blob/e80cfb7c9f78eccca76a6ddbec742c89612d4a03/entrypoint.sh#L31-L38)). `workshop_log.txt` records lines such as `Upload workshop item <id> failed (no workshop depot found)` **[community]** ([Weilbyte #5](https://github.com/Weilbyte/steam-workshop-upload/issues/5)). Valve points to `*.log` files and `logs\content_log.txt` for SteamPipe errors **[doc]** ([Uploading to Steam](https://partner.steamgames.com/doc/sdk/uploading)).
- **Independent check.** `ISteamRemoteStorage/GetPublishedFileDetails` is a keyless POST that returns an item's details, so the action can confirm an update without parsing steamcmd **[doc]** ([ISteamRemoteStorage](https://partner.steamgames.com/doc/webapi/ISteamRemoteStorage)).

## Recommendation

**E4:** use the cached session (`config.vdf`), with native steamcmd on `ubuntu-latest`.

1. Generate the session interactively by running steamcmd locally on Linux (WSL or a container) as @s-tyda. This rules out a Windows-to-Linux token mismatch. Store it gzip+base64 as an environment secret.
2. In CI, run `+login <user>` with no password, and pass `+workshop_build_item` an absolute VDF path outside the mod folder.
3. Close stdin and set a step timeout, so that a Steam Guard prompt fails the step instead of hanging it.
4. Update an existing private test item. Judge success by the VDF, `workshop_log.txt` and `GetPublishedFileDetails`, not by the exit code alone.
5. Log only redacted results. Never print `config.vdf`.

**Modders (v1 default):** the same cached session.

- It needs no password or 2FA secret in GitHub, works with email or mobile Steam Guard, and can be revoked by deauthorizing devices.
- The cost is a manual refresh when Steam ends the session (`License expired` or a Steam Guard prompt). The action should detect this and print the re-login steps.
- TOTP (password + `shared_secret`) is an opt-in for people who already run steamguard-cli or a similar tool. The docs must say plainly that those secrets add up to the whole account.
- Local mode remains the answer for anyone who will not put any Steam credential in CI.

## Open risks for E4 to check

1. **Lifetime and rotation.** Does steamcmd rewrite `config.vdf` after a successful CI login? Compare hashes before and after, without printing the file. Does the original secret still work on runs 2 to N and after several weeks? If the file rotates, decide between a write-back to the secret (this needs a PAT with secret-write rights) and a periodic manual refresh.
2. **Portability.** Does a `config.vdf` made on Linux work on `ubuntu-latest`, and one made on Windows on `windows-latest`? Try a Windows-made file on Linux once. Does the session survive many different runner IPs, or does Steam ask for a code or send "new login" emails?
3. **App 236850 accepts `workshop_build_item`.** Look for `no workshop depot found` in the logs, as on some apps. Repeat once for one `metadata.json` game (for example Victoria 3, which a modder already publishes this way with local steamcmd: [update_bpm.sh](https://github.com/Better-Politics-Mod/Better-Politics-Mod-Vic-3/blob/f02230c35eeb5bce4244ce5ee04c231007774679/update_bpm.sh)).
4. **Success and failure signals.** Record the real console output, the exit code, `publishedfileid` written back, `workshop_log.txt` and `depot_build_236850.log` for one success, one deliberate login failure and one deliberate bad VDF.
5. **Fidelity.** Are files byte-identical after download (cf. steam-for-linux #3997)? Do title, description, tags, preview and visibility stay unchanged when their keys are left out of the VDF (E3 showed this only for ISteamUGC)?
6. **Prompts and holds.** Does any run hang on a Steam Guard prompt? Do throttle (87) or rate-limit (84) results appear when runs follow each other within minutes? Does a password change on the account stop CI from publishing, and for how long (`ServiceReadOnly`)?
7. **Secret hygiene.** Is the gzip+base64 size under 48 KB? Is the session absent from logs, artefacts and the Actions cache?
