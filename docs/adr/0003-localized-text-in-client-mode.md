# Localized titles and descriptions are set in `client` mode only

Steam stores a Workshop item's title and description per language: `ISteamUGC::SetItemUpdateLanguage` names the API language code (`schinese`, `japanese`, `koreana`, …) of the title and description in one item update, and `english` is assumed when it is not set. `steamcmd +workshop_build_item` has no such key. Valve's guide lists `appid`, `publishedfileid`, `contentfolder`, `previewfile`, `visibility`, `title`, `description` and `changenote`, and the strings of `steamconsole64.dll` (the steamcmd build of 2026-10-22) name only those plus `filetype` and `kvtags` next to `workshop_build_item`, with no `language`. Without a language key in the steamcmd code, a `language` key in the VDF would at best be ignored and the localized text would overwrite the English one. We therefore set *localized texts* in `client` mode only, like tags (ADR 0002): one extra item update per language after the main one, each with only the language, the title and the description. `steamcmd` mode publishes the English title and description, which leave the other languages as they are. The plan marks localized texts as `client` mode only, as it does for tags, and `publish` in `steamcmd` mode warns that they must be published with `pdx-ws publish --mode client`.

## Consequences

- A localized text is defined next to its English source: `workshop/description.<language>.md` (or `.bbcode`) beside the configured `description`, and the title in a `titles` table of the `[[mod]]`. Unknown language codes are errors, and so is `english`, which the descriptor and `description` already give.
- Every language update sets both fields: its own title or the English one, its own description or the English one (when `description` is set), so no language is left with an empty field.
- Deleting a localized file does not remove that language from Steam, which keeps the last text sent; the guide says so.
- Showing a player the text in their Steam client's language, and the English one when there is none, is Steam's behaviour, not something `pdx-ws` does. Valve's pages document only that `english` is assumed when no language is set.
